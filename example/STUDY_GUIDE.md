## 1. 현재 구현된 코드의 레벨은 어느 정도인가요?

결론부터 말씀드리면 **"초급~중급 사이(주니어 개발자 입문 수준)"**입니다.

- **왜 완전 초보자(입문) 코드보다는 한 단계 위인가요?**
  - 한 파일이나 한 함수에 모든 코드를 뒤섞어 놓지 않고, **역할별로 5개의 파일(모듈)로 깔끔하게 분리**했습니다.
  - 인터넷이 끊기거나 API 키가 틀렸을 때 프로그램이 외계어(Traceback)를 뱉으며 죽지 않도록 **예외 처리(`try ~ except`)**가 꼼꼼히 들어가 있습니다.
  - 함수의 입력과 출력이 무엇인지 알려주는 **타입 힌트(`-> str`, `List[str]`)**를 사용해 읽기 쉽습니다.
- **왜 어려운 전문가(시니어) 코드는 아닌가요?**
  - 복잡한 객체지향 클래스 상속(OOP), 비동기 프로그래밍(`async/await`), 무거운 외부 프레임워크를 전혀 쓰지 않았습니다.
  - 오직 **파이썬에 기본으로 내장된 도구(표준 라이브러리)**와 **기본 함수(`def`), 조건문(`if`), 반복문(`for`), 문자열 다루기**만으로 작성되어 있어 초심자도 한 줄씩 따라 읽으며 100% 이해할 수 있습니다.

## 3. 코딩 시작 전 알아야 할 핵심 개념 6가지

직접 코드를 짜기 전에 아래 6가지 부품이 무슨 역할을 하는지만 이해하면 절반은 끝난 것입니다!

### 개념 ① `subprocess` — 파이썬에게 터미널 명령어 대신 치게 하기
우리가 터미널에 직접 `git status`, `git diff`를 치면 화면에 글자가 나오듯, 파이썬 코드 안에서 그 명령어를 대신 실행하고 결과 글자를 변수에 담아오는 도구입니다.

```python
import subprocess

# 터미널에 `git status --porcelain`을 입력한 결과를 result 변수에 담기
result = subprocess.run(["git", "status", "--porcelain"], capture_output=True, text=True)
print(result.stdout)  # 출력된 글자 확인
```
- `capture_output=True`: 화면에 바로 출력하지 말고 파이썬 변수로 잡아채라!
- `text=True`: 컴퓨터 기계어(바이트)가 아니라 사람이 읽는 글자(`str`)로 달라!

---

### 개념 ② `os.getenv` — 비밀 API 키를 안전하게 숨겨서 불러오기
API 키는 내 계정의 비밀번호나 신용카드 번호와 같습니다. 코드 안에 `api_key = "sk-1234..."`처럼 직접 적어두고 GitHub에 올리면 전 세계 해커들에게 노출됩니다(이를 **하드코딩**이라고 하며 절대 금지됩니다).

대신 터미널에서 `export AI_API_KEY="내_진짜_키"`라고 운영체제 메모리(환경변수)에 등록해 두고, 파이썬은 이름표만 불러서 값을 꺼내 씁니다.

```python
import os

api_key = os.getenv("AI_API_KEY")  # 환경변수에서 꺼내오기 (없으면 None)
if not api_key:
    print("[ERROR] AI_API_KEY 환경변수가 설정되지 않았습니다.")
```

---

### 개념 ③ REST API와 JSON — AI 서버와 대화하는 택배 시스템
내 컴퓨터에 있는 파이썬 프로그램이 OpenAI나 Google 서버에 있는 AI에게 글을 써달라고 부탁하려면 인터넷으로 편지(HTTP 요청)를 보내야 합니다. 이를 **REST API 호출**이라고 부릅니다.

택배를 보낼 때 3가지가 필요합니다:
1. **URL (주소)**: 어디로 보낼지 (예: `https://api.openai.com/v1/chat/completions`)
2. **Headers (운송장/신분증)**: 내가 정식 사용자인지 증명하는 `API Key`와 내용물이 `JSON`이라는 표시
3. **Body / Payload (택배 상자 내용물)**:
   - `model`: 어떤 AI 모델을 쓸지 (`gpt-4o-mini`, `gemini-2.0-flash` 등)
   - `messages`: 우리가 만든 프롬프트(지시문)
   - `temperature`: **창의성 조절 다이얼** (`0.0`에 가까우면 차분하고 규칙적인 모범생 답변, `1.0`에 가까우면 매번 달라지는 창의적 답변. 커밋/PR 요약은 `0.2 ~ 0.3`이 가장 좋습니다.)
   - `max_tokens`: **최대 글자(토큰) 수 제한** (AI가 너무 길게 소설을 써서 요금이 많이 나오는 것을 방지)

---

### 개념 ④ 프롬프트 엔지니어링 — AI에게 명확한 작업 지시서 주기
AI에게 그냥 코드만 던져주면 중구난방으로 대답합니다. 그래서 두 부분으로 나누어 지시합니다.
- **System Prompt (역할과 절대 규칙)**: *"너는 숙련된 개발자야. 첫 줄은 무조건 50자 이내 제목으로 쓰고, PR 본문은 반드시 `## Why`, `## What`, `## How to Test` 헤더와 불릿(`- `)을 넣어서 작성해!"*
- **User Prompt (분석할 재료)**: 실제 수집한 `git status` 파일 목록과 `git diff` 코드 내용

---

### 개념 ⑤ 문자열 다루기와 정규표현식(`re`) — 검수 및 마스킹
1. **문자열 후처리 (`validator.py`)**:
   - AI가 가끔 규칙을 어기고 제목을 90자로 길게 줄 수 있습니다. 이때 `if len(title) > 72: title = title[:69] + "..."`처럼 파이썬 코드로 길이를 잘라주면 추가 API 비용 없이 100% 규칙을 지킬 수 있습니다.
2. **정규표현식 마스킹 (`git_collector.py`의 `-safe-mode`)**:
   - `re.sub(찾을_패턴, 바꿀_글자, 원본_글자)`를 사용하면 이메일이나 API 키처럼 생긴 문자열을 찾아서 `[MASKED]`로 한 번에 가릴 수 있습니다.

---

### 개념 ⑥ `argparse` — 터미널 명령어와 옵션 스위치 만들기
`python main.py commit -temperature 0.5 -safe-mode`처럼 실행했을 때, 사용자가 `commit`을 골랐는지 `pr`을 골랐는지, `-temperature` 숫자는 몇을 넣었는지 자동으로 분석해 주는 파이썬 기본 도구입니다.

## 4. 백지에서부터 직접 만들어보는 5단계 구현 순서

처음부터 5개 파일을 다 만들려고 하면 헷갈립니다. **반드시 아래 순서대로 하나씩 만들고 테스트하며 조립하세요.**

### Step 1. Git 변경 사항 가져오는 `git_collector.py` 먼저 만들기
1. `run_git_command()`와 `collect_git_changes()` 함수를 작성합니다.
2. 파일 맨 아래에 임시로 `print(collect_git_changes())`를 적고 실행해 봅니다.
3. 내 프로젝트의 변경된 파일 이름과 `git diff` 내용이 터미널에 잘 찍히는지 확인합니다.
4. 잘 된다면 `apply_safe_mode()` 함수를 추가해 줄 수 자르기(`[:200]`)와 마스킹(`re.sub`)을 붙입니다.

### Step 2. AI 서버와 통신하는 `ai_client.py` 만들기
1. `get_api_key()` 함수를 만들어 환경변수 `AI_API_KEY`를 읽어옵니다.
2. `call_ai_api()` 함수를 작성합니다.
3. 임시로 `"너는 친절한 도우미야"`, `"안녕? 한 줄로 인사해줘"`를 넣어 AI의 대답이 터미널에 잘 도착하는지 확인합니다.
4. 일부러 틀린 API Key를 넣어보고 `401 인증 실패` 에러 메시지가 친절하게 뜨는지 확인합니다.

### Step 3. 프롬프트 조립기 `prompts.py` 만들기
1. `build_commit_prompt()`와 `build_pr_prompt()` 함수를 만듭니다.
2. 미션 문서에서 요구하는 규칙(커밋 제목 1줄 + 불릿 요약 / PR 제목 + `Why`, `What`, `How to Test` 섹션)을 System 프롬프트 문자열에 꼼꼼히 적어줍니다.

### Step 4. 결과 검수기 `validator.py` 만들기
1. `validate_and_refine_commit()` 함수에서 제목 길이(72자)와 불릿 포함 여부를 체크합니다.
2. `validate_and_refine_pr()` 함수에서 제목 길이(80자)와 `## Why`, `## What`, `## How to Test` 섹션이 빠지지 않았는지 검사하는 코드를 작성합니다.

### Step 5. 매니저 파일 `main.py`에서 하나로 합치기
1. `build_arg_parser()`로 `commit` / `pr` 명령어와 `-model`, `-temperature`, `-max-tokens`, `-safe-mode` 옵션을 등록합니다.
2. `main()` 함수 안에서 앞서 만든 1~4번 파일의 함수들을 순서대로 호출하고, 구분선(`--- Commit Message ---` 등)과 함께 출력하면 완성입니다!

## 5. 과제 목표(셀프 체크 / 평가 대비) 핵심 Q&A

미션의 **[3. 과제 목표]**에 있는 5가지 질문을 스스로 설명할 수 있는지 확인해 보세요.

1. **Q. AI API를 REST API 방식으로 연동하는 전체 흐름은 무엇인가요?**
   - **A.** 환경변수에서 API Key를 불러와 HTTP 요청 헤더(`Authorization`)에 담고, 프롬프트와 파라미터를 JSON 형태의 Body로 구성해 POST 요청을 보냅니다. 응답을 받으면 JSON을 파싱해 텍스트를 추출하고, 네트워크 단절(`URLError`)이나 인증 실패·한도 초과(`HTTPError` 401/429) 같은 예외를 처리합니다.
2. **Q. `temperature`와 `max_tokens`는 결과 품질에 어떤 영향을 주나요?**
   - **A.** `temperature`는 생성 문장의 무작위성(창의성)을 조절합니다. 커밋/PR처럼 정해진 템플릿과 사실 기반 요약이 중요할 때는 낮게(`0.2~0.3`) 설정해야 일관된 품질이 나옵니다. `max_tokens`는 생성할 최대 토큰 길이를 제한하여 불필요하게 긴 응답과 과도한 API 비용을 방지합니다.
3. **Q. `git status`, `git diff`를 프로그램 입력으로 연결하는 흐름은 어떻게 되나요?**
   - **A.** 파이썬 `subprocess.run()`으로 두 명령어를 실행해 표준 출력(`stdout`)을 문자열로 캡처한 뒤, 변경 사항이 없으면 즉시 종료하고, 변경 사항이 있으면 파일 목록과 diff 텍스트를 프롬프트에 삽입해 AI에게 전달합니다.
4. **Q. 원하는 양식의 커밋/PR 요약을 얻기 위해 프롬프트를 어떻게 설계했나요?**
   - **A.** System 프롬프트에 역할(숙련된 엔지니어)과 명확한 출력 제약 조건(Conventional Commits 제목, 글자 수 제한, PR의 `## Why`, `## What`, `## How to Test` 헤더 및 불릿 필수)을 명시하고, User 프롬프트에 브랜치명·변경 파일 목록·diff 컨텍스트를 구조화하여 전달했습니다.
5. **Q. 생성된 텍스트를 코드로 한 번 더 검증하고 다듬는(후처리) 이유는 무엇인가요?**
   - **A.** AI 모델은 확률적으로 문장을 생성하므로 프롬프트로 지시하더라도 간혹 글자 수를 초과하거나 마크다운 코드 블록(` ``` `)을 포함하거나 특정 섹션을 누락할 수 있습니다. 이를 파이썬 후처리 코드로 검증·보정하면 추가 API 재호출 비용 없이도 실무 규칙을 100% 만족시킬 수 있습니다.
